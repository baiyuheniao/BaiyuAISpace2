# 自主维护交接日志

## 2026-08-17：将现有 Rust 单元测试接入 CI

### 变更

- 在 `.github/workflows/ci.yml` 的 Windows 与 Ubuntu 矩阵中增加
  `cargo test --manifest-path src-tauri/Cargo.toml`。
- 测试步骤位于前端构建和 Rust 编译检查之后，任一单元测试失败都会阻止合并。

### 根因与用户影响

仓库已有约 65 个 Rust 单元测试，覆盖 Agent Team 数据库与命令辅助逻辑、LLM 请求体、
RAG 文档解析和检索等关键路径，但原 CI 只运行 `cargo check`。代码即使破坏了已有测试
所描述的行为，只要仍能编译就会被放行。

人话解释：原来仓库里已经写了不少“自动验收题”，但流水线从来没有真正答这些题；
现在每次提交都会在 Windows 和 Ubuntu 上执行它们，答错就不允许合并。

### 验证

- 工作流语法和命令路径已静态核对。
- 由本次 PR 自身的 GitHub Actions 首次执行完整测试矩阵；只有 Windows、Ubuntu
  两个平台的构建、编译和测试全部通过后才合并。

### 风险与回滚

- 仅增加 CI 验证时间，不修改应用运行时逻辑、数据库或发布产物。
- 若发现测试依赖特定平台或环境，将修复测试隔离问题；不会通过删除测试规避失败。

### 下一步

- 逐步把 Agent Team 冒烟测试拆出不依赖真实模型的确定性集成测试。
- 将 Issue #86 的超时行为做成可控的本地 HTTP 测试后再决定恢复策略。

## 2026-08-17：Agent Team 全局事件监听竞态

### 变更

- 为 `src/stores/workspace.ts` 的 `initListeners()` 增加初始化中的 Promise 互斥。
- 并发调用现在复用同一轮监听器注册，不会分别注册两套全局监听器。
- 注册过程失败时主动注销已经成功注册的部分监听器，保留后续重试能力。
- 消息、活动日志及五类待处理事项增加按事件 ID 去重，防止重复事件污染界面状态。

### 根因与用户影响

`Layout.vue` 和 `AgentTeamView.vue` 都会在挂载时调用 `initListeners()`。旧代码只通过
`unlistenFns.length` 判断是否已经初始化，而该数组要等所有异步 `listen()` 完成后才会赋值。
两处调用重叠时都会看到长度为 0，从而注册两整套监听器。用户可能看到同一条 Agent 消息、
日志或审批卡片出现两次；重复审批还会触发“事项不存在或已处理”的二次错误。

人话解释：应用启动 Agent Team 页面时，原来可能把同一个“消息接收器”装两遍，因此一条消息
会被界面接收两次。现在同一时刻只允许安装一次，并且相同编号的事件只展示一次。

### 验证

- 静态路径核对：`Layout.vue` 与 `AgentTeamView.vue` 的并发入口均会命中同一个初始化 Promise。
- 重复事件核对：消息、日志使用后端事件 `id` 去重；提议、休眠、轮数、提问、工具审批分别使用自身 ID 去重。
- 本地完整构建暂不可执行：当前运行环境缺少 Rust 工具链，且前端依赖镜像无法从受限网络下载。
- 提交后由仓库现有 GitHub Actions 执行前端构建与 Rust 编译门禁；在门禁通过前不合并或发布。

### 风险与回滚

- 变更只影响前端事件订阅与内存队列，不修改 SQLite、Agent 推理或工具执行逻辑。
- 若出现监听初始化异常，可回滚本次提交；失败分支会清理部分注册，避免残留半套监听器。

### 下一步

- GitHub Actions 通过后，在 Windows 真实应用中快速切入 Agent Team，确认单条消息、日志与审批卡片均只出现一次。
- 继续复现 Issue #86 的 600 秒非流式请求超时；在取得真实超时证据前不拍脑袋修改上限。
